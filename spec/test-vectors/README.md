# Test Vectors

Test vectors are the **ultimate arbiter** of the spec. They are generated by the Rust reference implementation and **independently verified by the TypeScript SDK** before milestone M1 closes (see `AGENTS.md` §4).

## Layout (to be generated, M1-05)
```
test-vectors/
  canonical/      # input JSON-ish → expected dag-cbor hex + CID
  identity/       # genesis/rotate/delegate/revoke chains + validity at given ts
  events/         # full valid case lifecycles + invalid mutations (each with expected error code)
  sealing/        # fixed keys/nonces/salts → expected ciphertext, commit, wrapped keys (TEST_ONLY keys)
  scoring/        # claim sets → exact expected metrics (see SCORING.md §9: basic-001)
  sync/           # RECON transcripts for known sets
```

## Vector file format (`*.vec.json`)
```json
{
  "id": "scoring/basic-001",
  "spec": "SCORING.md#9",
  "description": "...",
  "input": { },
  "expected": { },
  "tolerance": 1e-9
}
```
Byte strings are lowercase hex. Invalid-case vectors include `"expected": {"error": "E_NONCANONICAL"}`.

## Rules
- Vectors MUST NOT contain real secrets; keys are `TEST_ONLY_`.
- Adding or changing a vector is a spec change (PIP) once the spec is Final.
- Every implementation (Rust, TS, Python, future) runs the full set in CI.
